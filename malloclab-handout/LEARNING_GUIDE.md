# Malloc Lab 学习指南

目标不是背下一份分配器代码，而是逐步回答一个问题：程序怎样把一段连续字节，安全而高效地分给多次 `malloc` 和 `free`？

## 0. 环境与入口

本目录已经适配 arm64 macOS。常用命令：

```sh
cd /Users/Administrator/Desktop/CSAPP_Labs/malloclab-handout
make
make check
./mdriver -V -f short1-bal.rep
```

只修改 `mm.c`。其他重要文件：

- `mdriver.c`：读取 trace，检查正确性、利用率和吞吐量。
- `memlib.c`：用一块数组模拟堆，`mem_sbrk(n)` 只会把堆顶向后移动。
- `short1-bal.rep`、`short2-bal.rep`：最小测试序列。
- `config.h`：对齐、最大堆大小、计时方式等配置。

当前 `mm.c` 是故意写得很弱的起始版本：分配时向堆尾追加，`free` 什么也不做。它能过短 trace，但不能复用空间。

## 1. 最少前置知识

不要求先学完整本书。会下面六件事就可以开工；不熟的内容随实验补：

1. C 指针：`void *`、`char *`、取地址与解引用。
2. 指针运算：为什么移动 1 字节要先转成 `char *`。
3. 整数与位运算：`&`、`|`、掩码，以及二进制最低几位。
4. 结构体和宏：能读懂 `#define` 即可。
5. 内存布局：栈、堆只需知道用途不同；本实验只管理模拟堆。
6. 基本调试：编译警告、断言、在关键位置打印块信息。

自测：如果你能解释下面三行，就可以直接开始第 2 节；不能解释也没关系，它们就是第一课。

```c
char *next = (char *)bp + size;
size_t size = header & ~(size_t)0x7;
int allocated = header & 0x1;
```

## 2. 一次只理解一个概念

### 第 1 课：对齐

请求 13 字节时，实际块大小通常向上取整到 8 的倍数。这样地址便于 CPU 访问，也让块大小的最低 3 位恒为 0。

只需记住：`ALIGN(13) == 16`，`ALIGN(16) == 16`。

### 第 2 课：块 = 元数据 + 有效载荷

用户只看到 payload 指针；分配器还要在它前后保存状态：

```text
低地址                                             高地址
+----------------+----------------------+----------------+
| header         | payload              | footer         |
| 大小 + 已分配位 | 返回给用户的区域       | 大小 + 已分配位 |
+----------------+----------------------+----------------+
```

因为块大小已按 8 对齐，大小的最低位空闲，可用来保存 allocated：

```c
packed = size | allocated;
size = packed & ~(size_t)0x7;
allocated = packed & 0x1;
```

### 第 3 课：隐式空闲链表

从堆首开始，用 header 中的块大小跳到下一块。它叫“隐式链表”，因为没有真正的 `next` 指针。

本课只实现：遍历所有块，找到第一个足够大的空闲块（first fit）。

### 第 4 课：放置与分割

找到 64 字节空闲块，而请求只需 32 字节时：前半分配，剩余部分仍为空闲块。剩余空间太小时不分割，避免产生不可用的小碎片。

### 第 5 课：释放与合并

`free` 先把当前块标为空闲，再检查左右邻居。四种情况必须逐一画图：

1. 左右都已分配：不合并。
2. 左已分配、右空闲：向右合并。
3. 左空闲、右已分配：向左合并。
4. 左右都空闲：三块合并。

footer 的价值就在这里：它让我们从当前块快速知道前一块的大小。

### 第 6 课：扩展堆

找不到合适空闲块时，调用 `mem_sbrk` 扩展模拟堆，把新空间变成空闲块，再与原堆尾空闲块合并。

### 第 7 课：`realloc`

先写正确版：申请新块、复制 `min(旧 payload, 新请求)` 字节、释放旧块。正确后再优化原地扩张。

### 第 8 课：堆检查器

实现 `mm_checkheap`，至少检查：

- 每个 payload 是否 8 字节对齐；
- header 与 footer 是否一致；
- 块大小是否合法，是否越过堆边界；
- 是否存在两个相邻但未合并的空闲块。

它不是附加功能，而是完成实验最快的工具。

### 第 9 课：性能优化

正确以后再从隐式链表升级到显式空闲链表、分离适配链表。不要一开始就做高级结构，否则链表错误和块布局错误会混在一起。

## 3. 推荐实现顺序

每一步都要求 `make check` 仍通过，再进入下一步：

1. 写读写 header/footer、取块大小、取分配位的宏或内联函数。
2. `mm_init` 建立序言块和结尾块。
3. `extend_heap` 扩展堆。
4. `find_fit` 首次适配查找。
5. `place` 放置并分割。
6. `mm_malloc` 串起查找、放置和扩展。
7. `coalesce` 与 `mm_free`。
8. 写正确但朴素的 `mm_realloc`。
9. 写并频繁调用堆检查器。
10. 最后优化利用率和吞吐量。

## 4. 第一阶段验收标准

在动手实现分配器前，应当能口头回答：

- 为什么块大小要对齐？
- 为什么对齐后可把 allocated 放进 size 的最低位？
- payload 指针与 header 指针相差多少字节？
- `mem_sbrk` 返回什么，失败时返回什么？
- 为什么只实现 `free` 标记、不做合并会产生碎片？

答不出来时，回到对应小节画一个 3 块堆图；不需要继续阅读更多理论。
